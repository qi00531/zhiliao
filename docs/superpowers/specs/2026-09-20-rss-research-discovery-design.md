# 知了 RSS 接入、自动研究与搜索发现设计

日期：2026-09-20
状态：已确认设计，等待用户审阅书面规格

## 1. 目标与范围

本阶段建立第一条可生产化的公开信源闭环：用户接入 RSS 或普通网址，系统持续发现更新；对符合用户目标和动态记忆的重要内容进行后台联网研究；将佐证附着到内容，将具有独立价值的新发现作为一条新信息展示；用户确认后再将可复用认识沉淀进知识库。

本阶段不接入其他私有信源，不让 AI 直接负责抓取，不把搜索结果自动变成长期订阅，也不自动将研究结果写入知识库。

## 2. 产品原则

- 采集、解析、增量识别、去重、游标和失败状态由确定性代码负责。
- AI 只负责相关性判断、聚类、比较、压缩与组织，不负责操作信源。
- 首页只显示值得注意的变化；详情、摘要、历史和证据默认折叠。
- 搜索结果不能逐篇倾倒给用户，必须先去重、聚类和判断价值。
- 所有结论都能回到可点击的来源和证据。
- 搜索发现与已接入信源的更新必须明确区分。
- 用户记忆长期形成并动态变化，不能用一次点击固化兴趣。

## 3. 接入入口

统一入口使用一句提示：

```text
输入 RSS、网址或关键词
```

系统根据输入类型处理：

1. RSS、Atom 或 JSON Feed 地址：解析并展示信源预览，用户一键接入。
2. 普通网址：检查网页声明的 Feed 和常见 Feed 地址；发现多个时让用户选择。
3. 未发现 Feed 的网址：提供“监控此网页”，作为独立的网页变化连接器，不伪装成 RSS。
4. 关键词或名称：在内置常用来源目录中检索，展示可以一键接入的候选信源。

来源卡片只显示名称、域名、一句说明和“接入”状态。Feed 地址、发现方式、频率与错误记录进入折叠详情或统一设置。

## 4. RSS 首次接入与持续抓取

### 4.1 首次接入

- 默认保存最近 20 条为基线。
- 首页最多显示最近 3 条，并标记“首次导入”。
- 其余历史内容默认折叠，不产生提醒。
- 用户可选择“不导入历史，从现在开始”。
- 首次导入的历史内容不触发自动研究。

### 4.2 增量识别

条目依次使用以下标识去重：

1. Feed 提供的稳定 `guid` 或等价 ID。
2. 规范化后的原文链接。
3. 标题、发布时间和来源组成的稳定哈希。

同一条目内容发生变化时保存修订，不重新创建条目。抓取失败不得推进游标，也不得解释为“没有更新”。

### 4.3 抓取策略

- 优先使用 ETag、Last-Modified 和 Feed TTL。
- 默认使用自适应频率，依据历史更新规律、连续无更新、错误状态与用户关注程度调整。
- 用户只在统一设置中选择自动、更及时、更节制或暂停。
- 网络错误、格式错误、限流、服务器错误和 Feed 消失必须分别记录。

## 5. 网页变化监控

普通网址未发现 Feed 时，用户可以明确选择“监控此网页”。系统提取稳定正文区域并建立内容指纹，过滤导航、广告、时间戳和其他高频模板变化。

首次扫描只建立基线。后续只有有效正文变化才生成内容；每次变化保留时间、内容哈希、变化片段和可回看的来源快照。网页监控与 RSS 使用相同的标准化事件接口，但保留不同的连接器类型和错误状态。

## 6. 用户动态记忆

用户记忆用于判断哪些内容值得研究，由以下信号共同形成：

1. 用户指定的目标：最高权重，不自动消失。
2. 已接入信源：表示长期接收意愿，但不代表喜欢其中每条内容。
3. “忽略”：明确负反馈；一次忽略降低相似内容权重，不永久屏蔽整个主题。
4. 自然使用行为：展开摘要、查看证据、查看历史、保存知识和追问等弱信号；停留时间不能单独作为判断依据。

记忆区分当前目标、长期关注、近期关注和减少关注。近期兴趣随时间较快衰减，长期关注缓慢变化；完成的目标进入历史，不再持续影响首页。

用户可在设置中查看并修正系统形成的记忆。页面只展示少量主题和“调整”“减少此类内容”，判断依据默认折叠。

## 7. 自动补充研究

### 7.1 设置与触发

统一设置提供：

```text
自动补充研究                         [开关]
```

默认关闭。开启后，新内容接入时立即进入后台判断，不等待用户打开。系统先用规则排除重复、过期、首次导入历史和被频繁忽略的内容，再结合用户目标、信源、动态记忆和知识库，由 AI 判断剩余内容是否值得研究。

用户尚未设置目标时，仍可依据信源和动态记忆判断，但采用更高触发门槛。自动研究设置每日限额，优先处理相关性和潜在价值更高的内容。

关闭后停止创建新的自动研究任务，保留已有结果；用户仍可对单条内容手动发起研究。

### 7.2 研究任务

研究围绕内容中的核心事实、数据、观点、背景和潜在影响检索。优先采用官方材料、原始文件和第一手来源；二手材料用于补充传播情况或呈现分歧。

任务状态包括等待研究、研究中、已完成、部分完成和暂时失败。任务失败不影响内容展示、不打扰用户，也不生成红点；重试沿用同一任务，避免重复结果。

研究完成后不通知用户。用户再次打开该内容时，在正文下看到默认折叠的“研究补充 · 已完成”；进行中显示“研究补充 · 整理中”。

## 8. 证据与搜索发现

研究材料聚类后分为四类：

1. 支持、质疑或补充已有内容的材料：作为证据附着到该内容。
2. 形成独立新事实、新进展或新认知的材料：生成一条“搜索发现”。
3. 只是重复表达且没有新增价值的材料：丢弃。
4. 来源相互冲突：标记“存在分歧”，不强行给出统一结论。

### 8.1 证据

证据显示其支持或质疑的具体结论，并保存标题、网址、发布者、抓取时间和必要片段。证据使用与“查看来源”一致的来源查看器，可以点击回到原文。

### 8.2 搜索发现

搜索发现作为一条独立信息进入首页，而不是藏在原内容内部。它必须：

- 由多篇材料聚合成一条信息，不逐篇展示搜索结果。
- 具有独立价值和至少一项可点击证据。
- 标记“搜索发现”，不能伪装成已接入信源的更新。
- 显示“由某条内容延伸发现”，并能回到触发内容。
- 与已有事件去重；同一事件只展示一次并保留多项证据。
- 不自动将搜索到的网站变成长期信源。
- 可以被打开、查看来源和证据、查看关联、忽略，并参与后续知识沉淀。

搜索发现的视觉层级弱于用户主动接入信源的更新，但遵循相同的简洁内容结构。

## 9. 首页与交互

首页主要展示两类信息：

```text
已接入
RSS 解析应保留失败状态
来源：某技术博客

搜索发现
多个 Feed 时应让用户主动选择
由上方内容延伸发现 · 来源 3
```

标题、来源和时间构成默认视图。摘要、研究补充、历史变化、相关内容与完整证据默认折叠。“查看来源”和“查看证据”使用相同抽屉结构。

“忽略”在后续加入首页内容操作。忽略影响动态记忆和相似内容的研究优先级，但不删除原始记录，也不永久屏蔽整个主题。

## 10. 知识沉淀

首页负责“发生了什么”，知识库负责“最终形成了什么认识”。已接入内容、证据和搜索发现都不能自动成为知识。

系统识别具有长期复用价值的认识后：

- 能补充已有主题时，建议在主题下新增或更新一条认识。
- 能修正旧认识时，保留旧版本、修订关系和依据，不直接覆盖。
- 没有对应主题时，建议创建主题。
- 只有用户确认后才写入知识库。

知识库以主题聚合同类认识，而不是每篇文章生成一个知识文件。每条认识都可以展开查看相关的已接入内容、搜索发现和原始证据；同类观点合并，来源与历史默认折叠。

## 11. 数据与组件边界

核心对象包括：

- `Source`：RSS、网站或网页监控对象。
- `Document`：抓取到的原始条目或页面版本。
- `Event`：一次真实发生的更新。
- `Change`：相对可靠历史状态的变化。
- `Evidence`：支持、补充或质疑某项结论的来源。
- `ResearchTask`：由内容触发的后台研究任务。
- `ResearchFinding`：研究生成的证据判断或独立搜索发现。
- `UserMemorySignal`：目标、信源、忽略和自然使用行为形成的动态信号。
- `KnowledgeTopic` 与 `KnowledgeClaim`：用户确认后沉淀的主题和认识。

总体数据流为：

```text
Source → Document → Event → Change → Evidence
                           ↓
                     ResearchTask
                      ↙         ↘
              Evidence      Search Finding
                      ↘         ↙
                    用户确认
                        ↓
              Knowledge Claim
```

RSS 解析器、网页变化检测器、研究调度器、搜索提供方、结果聚类器、动态记忆和知识库分别通过清晰接口连接。搜索提供方和模型提供方可以替换，不得把供应商格式写入领域对象。

## 12. 安全与异常边界

- URL 获取必须阻止内网地址、环回地址、云元数据地址、危险重定向和超大响应，防止 SSRF。
- XML 解析禁止外部实体，限制文档大小和解析时间。
- 外部 HTML 必须清洗后展示，禁止执行脚本和不受信任嵌入。
- 搜索或模型失败不能阻塞 RSS 接入与首页内容展示。
- 证据访问失败时保留原记录并显示最后成功获取时间。
- 没有可靠来源或无法确认时明确显示“暂无法确认”，不得补写推测。
- 停用自动研究后，排队但尚未开始的自动任务取消；手动任务不受影响。

## 13. 验证要求

### 13.1 RSS 与网页接入

- 覆盖 RSS 2.0、Atom 和 JSON Feed 固定样本。
- 验证 `guid`、规范化链接和稳定哈希的增量去重。
- 验证首次导入、从现在开始、条目修订和抓取失败不推进游标。
- 验证单个、多个和没有 Feed 的网页发现流程。
- 验证网页模板噪声不会产生有效变化事件。

### 13.2 自动研究

- 验证关闭设置后不产生自动任务。
- 验证首次导入历史不会触发研究。
- 验证无目标时使用更高门槛。
- 验证同一事件只创建一个研究任务和一条搜索发现。
- 验证失败、重试、部分完成和每日限额。

### 13.3 结果与知识库

- 验证证据、搜索发现、重复材料和分歧材料的分类。
- 验证搜索发现拥有触发内容、来源和证据关系。
- 验证搜索发现不会自动订阅新信源。
- 验证未经用户确认的内容不会写入知识库。
- 验证知识修订保留旧版本及依据。

### 13.4 产品呈现

- 验证首页默认只显示标题、来源和时间。
- 验证研究结果完成后无通知、无红点。
- 验证用户重新打开内容后可以看到折叠的研究补充。
- 验证“查看来源”和“查看证据”使用同一展示方式。

## 14. 实施边界与顺序

后续实施计划按以下顺序拆分：

1. RSS 手动接入、存储、调度、去重与证据。
2. 普通网址 Feed 自动发现与内置常用来源一键接入。
3. 无 Feed 网页的变化监控。
4. 用户目标、动态记忆和“忽略”信号。
5. 自动研究任务、联网搜索、证据聚类与搜索发现。
6. 用户确认后的主题化知识沉淀。

每一阶段都必须保持前一阶段可独立运行，研究能力失败不得破坏信源采集主链路。
